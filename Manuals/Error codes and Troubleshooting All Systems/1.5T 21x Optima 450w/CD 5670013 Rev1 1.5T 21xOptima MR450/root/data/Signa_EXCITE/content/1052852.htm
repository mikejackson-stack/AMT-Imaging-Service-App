VRE Sensors Display

1  Diagnostic Link

Diagnostics >> System Function >> Recon >> VRE Sensors Display

Diagnostics >> Hardware Location >> PGR Cabinet >> Recon >> VRE Sensors Display

Illustration 1:  VRE Sensors Display

2  Purpose

This diagnostic displays the sensor values for all ICNs installed in the system. Three categories of sensor values are displayed: Fan Speeds, Temperatures, and Voltages. The display format includes the ICN number, sensor name, value and units, minimum value, maximum value, critical value and whether critical values were exceeded.

3  Requirements

All Ethernet cables must be connected from the Host to the Ethernet switch.

All Ethernet cables must be connected from the ICN to the Ethernet switch.

ICN is powered on.

4  Block Diagram

Illustration 2:  VRE Hardware Communication Block Diagram

5  Test Sequence

  1. Verify that all Ethernet cables are connected per Section 3.

  2. Execute the diagnostic by selecting the desired sensors.

  3. Verify that the sensor values display for all configured ICNs.

6  Expected Results

Table 1:  Expected Results

ResultDescriptionGE Field Action

Passed

The ICN has passed the diagnostic

No further action required

Failed

The ICN has failed the diagnostic

  1. Verify that the ICN is powered on.
  2. Verify that the Ethernet switch is turned on.
  3. Re-seat Ethernet cables from ICN to Ethernet switch and Host to Ethernet Switch.
  4. Run the Host ICN IPMI Path diagnostic and confirm that it passes. If it fails, follow the steps described in the help page for that diagnostic.
  5. Run the Host ICN Ethernet Path diagnostic and confirm that it passes. If it fails, follow the steps described in the help page for that diagnostic.
  6. Re-run this diagnostic after both Host-ICN IPMI Path and Host-ICN Ethernet Path diagnostics pass.
  7. If the diagnostic fails, run the following command and verify there are sensor files with non-zero size (except for theLAST_PULL file which is size zero): ls -1sh /usr/g/service/log/sensor_logs/*
NOTE:If the ICN Ethernet port/cables are bad then all of the tests for that ICN may fail (except the IPMI test which has a separate Ethernet cable).

Current product configuration has redundant motherboard Ethernet connections for each ICN.
