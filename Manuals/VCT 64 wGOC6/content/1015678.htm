2  Disk Array Overview

When troubleshooting the disk array, do not attempt to perform a hot swap. The disk is running at 10K RPM. Always HALT the console when performing cable or disk swapping. Without the HALT there is no guarantee that the Disk Array will recover properly. Perform the commands with Apps Down whenever possible. The only diagnostic command that should be performed with Apps Up is the query command: {ctuser@darc ~}$sudo gre-raid -q

2.1  Command Overview as [root@darc]

sg_map -i -x

grep(spacebar)'Curr:(spacebar)'(spacebar)/proc/scsi/aic79xx/*

2.2  Command Overview as {ctuser@darc}

sudo gre-raid(spacebar)-a (Non-Destructive ASSEMBLE)

sudo gre-raid(spacebar)-q (Non-Destructive QUERY/MAP)

sudo gre-raid(spacebar)-c (Destructive CREATE REPARTITION)

sudo gre-raid(spacebar)-s (STOP - UNMOUNT)

3  Disk Array Erase Serial Number Command

There may be times the Disk Array gets into a confused state and cannot be corrected. This may be due to a disk not being seen for a moment during the LFC, or due to create/assemble/query commands being run. This confusion does not occur often, but when it does the -z command may be used in conjunction with another diagnostic command (usually -c to erase the disk serial number, then reassemble).

NOTE:Erase the Disk Array serial numbers. Be careful when using the -z command. If a disk continues to fail, replace it. You must assemble after the erase.

{ctuser@darc ~}$sudo gre-raid -z -c

Then run:

{ctuser@darc ~}$sudo gre-raid -a

9  VDARC Node BIOS Telnet Reconfiguration Process

If the DARC SCSI BIOS "extended int 13 support for drives > 1GB" setting is disabled on either host controller, then gre-raid will fail to create/start the scan disk array (by design).

NOTE:SCSI controller settings for A and B “Sync Transfer Rate” should all be at 320 (not 160).

Ideally this one-time procedure would be done before the LFC. Use Serial Over LAN (SOL) to reboot the VCT DARC Node and access the DARC SCSI setup.

  1. With Application Software DOWN, open a Unix Shell:

    [root@darc ~]# service cliservice start

    Starting dpcproxy message or restarted dpcproxy message

    [root@darc ~]# telnet localhost 623

    [root@darc ~]# service cliservice start

    Server: darc

    Username: (press the enter/return key)

    Password: (press the enter/return key)

    At the dpccli prompt: reset

    Ok

    At the dpccli prompt: console

  2. Press Ctrl-A (when message appears) to configure the SCSI BIOS. Message appears shortly after system BIOS display.

  3. Press [Enter] to select AIC-7902 A at slot ##.

    1. Press Configure/View SCSI Controller Settings.

    2. Use down-arrow key to select SCSI Device Configuration.

    3. Verify that the Sync Transfer Rate (MB/Sec) for all is set at 320.

    4. If the Sync Transfer Rate (MB/Sec) is not set at 320, arrow to the value in need of change and press [Enter].

    5. Use up arrow key to 320 and press [Enter], then arrow over and select Enter> for next change.

    6. Verify that all (0 through 15) are set to 320.

    7. Press [Esc] to leave the Configuration screen for AIC-7902 A.

    8. Press [Esc] to leave this screen and return to AIC-7902 A at slot ## screen.

  4. At the AIC-7902 A at slot ## screen:

    1. Use the down-arrow key to select "Advanced Configuration" and press [Enter].

    2. Use down-arrow key to select "Extended Int 13 Translation for DOS Drives > 1 GByte".

    3. If setting is disabled, press [Enter] and select/enter "Enabled".

    4. Press the [Esc] key twice to go up two levels: (AIC-7902A Configuration screen, then Save Changes Made?).

    5. Select "Yes" to save changes.

    6. Press the [Esc] key to get out of the options screen: Configure/View SCSI Controller Settings.

  5. Press [Enter] to select AIC-7902 B at slot ##.

    1. Press Configure/View SCSI Controller Settings.

    2. Use down-arrow key to select SCSI Device Configuration.

    3. Verify that the Sync Transfer Rate (MB/Sec) for all is set at 320.

    4. If the Sync Transfer Rate (MB/Sec) is not set at 320, arrow to the value in need of change and press [Enter].

    5. Use up arrow key to 320 and press [Enter], then arrow over and select Enter> for next change.

    6. Verify that all (0 through 15) are set to 320.

    7. Press [Esc] to leave the Configuration screen for AIC-7902 B.

    8. Press [Esc] to leave this screen and return to AIC-7902 B at slot ## screen.

  6. At the AIC-7902 B at slot ## screen, use the down-arrow key to select "Advanced Configuration" and press [Enter].

    1. Use down-arrow key to select "Extended Int 13 Translation for DOS Drives > 1 GByte".

    2. If setting is disabled, press [Enter] and select "Enabled".

    3. Press [Esc] twice to go up two levels: (AIC-7902A Configuration screen then Save Changes Made?).

    4. Select "Yes" to save changes.

    5. Press [Esc] to get out of the options screen: Configure/View SCSI Controller Settings.

  7. Press [Esc] to leave this screen and return to AIC A/B Selection Screen.

  8. Press [Esc] to leave EXIT UTILITY? Use Arrow Key to select Yes, then press [Enter].

10  VDARC Node Replacement Loading and Saving Raw Data

  1. Shut down system and replace VDARC hardware.

  2. Remove VCT Disk Array power (2) cords from the rear of the VCT Disk Array power supplies or turn off both (2) power supplies located at the rear of the Disk Array.

  3. Boot system, stopping Application Software from coming up.

  4. Load software media following instructions from the appropriate LFC procedure:

    • DARC OS

    • DARC Apps (ignore any Disk Array errors)

  5. With Application Software down as ctuser, perform vrac_flash_update, answer "y".

  6. As root, halt the system.

  7. Attach VCT Disk Array (2) power cords to the rear of the VCT Disk Array power supplies or turn on both (2) power supplies located at the rear of the Disk Array.

  8. Boot the system but stop APPS from coming up.

  9. Assemble and query the Disk Array from the VDARC:

    {ctuser@darc}: sudo gre-raid -a

    {ctuser@darc}: sudo gre-raid -q

    NOTE:After booting up, the images will reconstruct automatically. No data is lost.

15  VDARC to Disk Array Part Overview

15.1  SCSI Channel 1

B (TOP) is Controller 1 and goes to the right side of the Disk Array, assuming that all 8 disks are seen. The letters are as follows. The numbers listed always stay the same. Lettering sometimes changes due to drop-out.

1(e)2(f)
3(g)empty
5(h)empty

15.2  SCSI Channel 2

A (BOTTOM) is Controller 0 and goes to the left side of the Disk Array, assuming that all 8 disks are seen. The letters are as follows. The numbers listed always stay the same.

1(a)2(b)
empty4(C)
empty6(D)

15.3  Procedure

  1. Run the Query / Assemble commands as needed to isolate a faulty side.

  2. After a side is isolated, mark that specific Ultra320 SCSI Cable as failed.

  3. Halt the system and swap the Ultra320 SCSI Cables.

  4. Ensure that both ends are swapped.

  5. Restart the system and stop apps from starting. See if the fault follows the Ultra320 SCSI Cable or remains on the original failing side.

  6. Note any failing drives. Mark all drives with their original location.

  7. Note any failing drives and mark them appropriately as well with fail??. A failing drive on one side will show an error, while the other side must DROP-OUT a drive and usually states not currently used. The DROPPED-OUT Drive is not a failure.

  8. Restart the system (via Halt) and stop Apps from starting. If a drive is actually failing there is no other work around--all data will be lost.

    NOTE:We can now attempt to see if the failure follows the drives or stays with the VDARC.

  9. As ctuser on the darc: sudo gre-raid -s then HALT.

21.1  Overview

The GOC5 VCT Operator Console is turned on or rebooted. At this point the VDARC Node is seen as RUNNING per the “ifconfig” command from the Host. The command “ping darc” fails. When the Application Software is started the VDARC Node fails to boot.

An Attention Box (Illustration 1) will pop-up stating that the Host is “Unable to verify system functionality on startup.”

Illustration 1:  Attention Box

21.3  Record Failures

If a VCT Disk Array (JBOD) failure is causing the VDARC Node to stop the booting process, the user identifies the failure as follows:

21.5  Identify Failures

21.5.1  Overview

A SMART issue you may encounter is when you find that the BIOS reports a problem with "Drive X on adapter Y," but when you swap Drive X it doesn't fix the problem. Chances are the documented mapping for the Adaptor/Controller does not match the reported mapping due to differences in the BIOS. (See Illustration 3.) In all likelihood, the mapping has been documented from the Host OS point of view. If Linux starts counting buses, channels, and luns at zero, but the BIOS or the SCSI adapter starts counting them at one, that would account for this discrepancy.

Currently several drives have been identified with the following failure message:

FAILURE PREDICTION THRESHOLD EXCEEDED [asc=5d,ascq=0]
unrecovered read error: "ASC=11 ASCQ=00, SelfTestByte=00, VendorSpecificByte=0F"

21.6  Working Around a Disk Failure

If one or two disk drives in the Disk Array are bad, the user may be able to continue running the Operator Console until the replacement drives arrive. However, all patient data not already backed up will be lost.

The Disk Array (JBOD) will allow a total of two disks to be dropped (from 8 to 6). Three disks must be good on each side of the Disk Array for Application Software to boot up and scan. If a total of seven disks are good and one disk is bad, only six disks will be used. A good disk from the other side will be dropped out until a good replacement disk is inserted and the gre-raid commands are performed. Additionally, the user is required to reconfig and regen the database when the replacement drive is inserted.

  1. Pull the first bad disk out of the Disk Array (JBOD).

  2. If a second bad disk is present, verify that it is inserted into the other side of the Disk Array by swapping it with a good disk drive.

  3. Do not insert any bad disks into the Disk Array.

  4. As long as only one bad disk is present on each side of the Disk Array (JBOD), the VDARC Node will successfully boot up and Application Software will start up. A message will be present in the gesyslog stating that six disks are present and the user may be informed by a pop-up window as well.

21.7  Ordering Disk Replacements

The VCT Operator Console is designed to run with eight disks present. Required replacement Disks for identified failing disk drives should be ordered immediately. The Disk Array FRU status may change.

21.8  Rebooting to Verify VDARC Node Boot

Perform a reboot command with Application software down. Verfiy that the VDARC Node boots up without user input and that the VCT System scans properly.

21.9  Replacement

  1. Refer to the LightSpeed Family for 7.x products.

  2. Select the Replacement tab.

  3. Select the Console tab.

  4. Select Disk Array (JBOD) FRU Replacements.

  5. Perform all required tests.

21.10  Regen the database in Reconfig

  1. With Application Software down, open a Unix Shell.

  2. Become root and perform the reconfig command.

  3. Select REGEN DATABASE and [Accept]. The Operator Console will reboot.
