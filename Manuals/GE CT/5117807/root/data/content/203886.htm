Xtream (GOC3) Console Tips

  • On Linux systems, the ↑↓(up and down arrows) scroll forward and backward through the most recent commands. Shortcut to history.

  • The power switch on the back of the IG or DARC is not the same as the power switch on the front. The switch on the front leaves the device in a standby state, similar to the way your television switch works. The standby state allows either the Host or DARC to reach it via the Serial Over LAN connection. The switch on the back is a hard power off switch that turns all power to the box OFF. It is recommended that the power switch on the back NOT be used.

  • If you shut down the console and it is at the Power Down prompt, you can restart the system by using < CTRL-ALT-DELETE> rather than turning power off and then on.

  • Remote terminal should be set to VT 100 compatibility.

  • It is okay to use telnet localhost 623 with applications running.

  • It was observed that with multiple users all logged into ig1 simultaneously that the connection locked up. It is not recommended that more than one user use telnet localhost 623 to a device at any given time.

  • hinv is currently not available on DARC or IG. May become available in the future.

  • scsistat is currently not available on the DARC. IG has no SCSI devices.

  • The SCSI bus on the DARC is running at half of the speed of possible maximum speed. The speed is sufficient for our data transfer needs and running at the lower speed creates a more stable bus.

  • The network ports on the HOST, DARC and IG are dedicated. This is because of the Serial Over LAN configuration. You cannot swap the connections around and expect the system to operate.

  • Intercom / Tilt diagnostics are currently not available. They are scheduled to be included in a future release of software. The board inside the SDDA is not replaceable. If the board is bad, replace the SDDA assembly.

  • The /var/log/messages file can get very long and pose a barrier to performance. So whenever the file size exceeds a certain limit (or by number of days expired), the Linux OS saves the current messages file into a file called messages.1, messages.2 etc., and write fresh on the messages file. So you may see files like messages, messages.1, messages.2 on the system.
