Host Computer USB Device Troubleshooting

Last Revised18 October 2005

1  USB Troubleshooting Overview

USB devices such as the Service Adaptor to Service Key and the Trackball and their associated interconnect paths must be recognized by the HOST during power-on boot-up for successful operation with Application software.

After determining a failure always perform a halt from root or Shutdown and then re-power the Operator Console to enable the USB device. This may be enough to have the HOST recognize the defective device.

With Apps up or down, you can plug a USB device into any port available on the front or rear of the Host Computer to determine if there is a bad:

  • Specific Host Port at rear of Operator Console

  • Trackball

  • Interconnect cable at rear of Operator Console

  • USB Feed-through for the Trackball at rear of Operator Console

  • USB Adaptor (for the Service Key located behind the Service Key Panel)

  • Interconnect cable from rear of Operator Console to USB Adaptor

1.1  USB Troubleshooting Methodology

Two Unix Shells will be opened and the user is required to be Root on the HOST for each.

Two sets of commands will be utilized to determine if a device and its path is recognized by the HOST.

The /var/log/messages will act as a real-time output log to determine device status and the lsusb command will be used to determine if the device information returned is healthy.

1.2  Synopsis

  1. Open a Unix Shell.

  2. Type: su -<Enter>

  3. At the password prompt, type: #bigguy<Enter>

  4. Type: lsusb -d0x----: -v (where ---- is the device)

  5. Type: tail -f /var/log/messages

    NOTE:Use <Ctrl>+<c> to exit the log.

The tail –f command will show the user the latest information as it occurs.

In this case you will be looking for the various USB ports to recognize a device when it is plugged in and recognize the device has been removed when it is unplugged.

Additionally, if the device is faulty intermittently the user can wiggle the cable or device and in some cases watch the device come and go for no reason.

2  Trackball Path Troubleshooting

2.1  Setup

  1. Plug the Trackball into the Host USB Port.

  2. Open a Unix Shell

  3. Type: su -<Enter>

  4. At the password prompt, type: #bigguy<Enter>

  5. Type: lsusb –d0x5223: -v<Enter>

    Good Output:

      iManufacturer       1 CST

      iProduct            4 CST USB UNITRAC

2.2  Log Review - Successful Test

  1. Open another Unix Shell

  2. Type: su -<Enter>

  3. At the password prompt, type: #bigguy<Enter>

  4. Type: tail –f /var/log/messages<Enter>

    Good Output Example:

      Oct 14 00:02:56 pygmy kernel: usb 5-1: new low speed USB device using address 2

      Oct 14 00:02:56 pygmy kernel: drivers/usb/input/hid-core.c: ctrl urb status -32 received

      Oct 14 00:02:56 pygmy last message repeated 2 times

      Oct 14 00:02:56 pygmy kernel: input: USB HID v1.00 Mouse [CST CST USB UNITRAC] on usb-0000:00:1d.3-1

  5. Press <Ctrl>+<c> to exit.

2.3  Log Review - Failed Test

  1. Remove the trackball from the USB Port.

  2. Type: tail –f /var/log/messages<Enter>

    Bad Output Example:

      Oct 14 00:07:22 pygmy kernel: usb 5-1: USB disconnect, address 2

      Oct 14 00:07:22 pygmy kernel: Device not ready. Make sure there is a disc in the drive.

      Oct 14 00:07:22 pygmy kernel: Device not ready. Make sure there is a disc in the drive.

      Oct 14 00:07:22 pygmy kernel: updfstab: Using deprecated /dev/sg mechanism instead of SG_IO on the actual device

  3. Press <Ctrl>+<c> to exit.

  4. Type: lsusb –d0x5223: -v<Enter>

    ***** No output is displayed *****

3  Security Key Adaptor Path Troubleshooting

  1. Plug the Service Key USB cable into the USB Adapter

  2. Open a Unix Shell

  3. Type: su -<Enter>

  4. At the password prompt, type: #bigguy<Enter>

  5. Type: lsusb –d0x067b: -v <Enter>
