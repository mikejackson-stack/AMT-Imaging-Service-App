🔌 GE MRI — Gather Load Data (GLD) Diagnostic
AMT Imaging Solutions — Field Service Quick Reference

Applies to: GE Signa Excite (9x–15x), HDxt, Discovery MR450/750, Optima 450w/750w — any platform with a Driver Module. Covers DD/TR Bias faults, multicoil errors, and dynamic disable (DD) troubleshooting using the Gather Load Data tool.
Why GLD? Gather Load Data is the fastest way to diagnose multicoil bias faults and dynamic disable (DD) faults without a phantom or scanning. Each troubleshooting pass takes about 1 minute. A full fault isolation from coil to pen panel to magnet typically takes <15 minutes total.

Multicoil Bias Fault Troubleshooting

Use this procedure when a multicoil error appears in the error log referencing a specific coil or coil channel.

Step 1 — Isolate the coil

  1. Identify the coil causing the error in the error log.
  2. Plug in the suspect coil.
  3. Set filename to mj1_bad_coil and run GLD.
  4. Open results: gedit /usr/g/service/log/mj1_bad_coil_mc.txt
  5. Find the channel number from the error log — verify it shows different values compared to the other good channels.

Step 2 — Confirm fault follows the coil

  1. Remove the suspect coil. Plug in a known-good multichannel coil.
  2. Set filename to mj2_good_coil and run GLD.
  3. Open results: gedit /usr/g/service/log/mj2_good_coil_mc.txt
  4. If the previously bad channel now looks normal → fault is in the original coil. Order the coil.
  5. If the bad channel is still present with the known-good coil → fault is in the system. Continue to Step 3.

Step 3 — Swap Driver Module cables to isolate

  1. Reconnect the known-good coil from Step 2.
  2. Swap cables on J5 and J10 on the back of the Driver Module.
  3. Set filename to mj3_dm_swap and run GLD.
  4. Open results: gedit /usr/g/service/log/mj3_dm_swap_mc.txt
  5. If the bad channel did not move → fault is in the Driver Module. Order Driver Module.
  6. If the bad channel moved → problem is between the Driver Module and the coil. Call TSM for support.
⚠️ RESTORE ALL CABLES BACK TO ORIGINAL POSITIONS BEFORE LEAVING SITE

Dynamic Disable (DD) Fault Troubleshooting

Use this procedure when the error log shows a DD BLD (front/back, 1/2/3/4) fault — either a short or an open on a dynamic disable line.

Step 1 — Establish baseline

  1. Unplug all coils from the system.
  2. Identify which DD BLD (front/back, 1/2/3/4) has the error and whether it's a short or open.
  3. Set filename to mj1_dd_base and run GLD.
  4. Open results: gedit /usr/g/service/log/mj1_dd_base_dd.txt
  5. Find the DD line noted in the error log — confirm it shows the bad value from the error.

Step 2 — Swap Driver Module DD cables

  1. Swap cables: BD1 ↔ BD4 and BD2 ↔ BD3 at the back of the Driver Module.
  2. Set filename to mj2_dm_swap and run GLD.
  3. Open results: gedit /usr/g/service/log/mj2_dm_swap_dd.txt
  4. If bad value did NOT move → fault is in the Driver Module. Order Driver Module.
  5. If bad value moved → fault is downstream. Restore Driver Module cables and continue.

Step 3 — Swap Pen Panel (equipment room side)

  1. Restore Driver Module cables to original positions.
  2. On the equipment room side of the Pen Panel swap: J92 ↔ J96 and J93 ↔ J95.
  3. Set filename to mj3_pp_eq and run GLD.
  4. Open results: gedit /usr/g/service/log/mj3_pp_eq_dd.txt
  5. If bad value did NOT move → fault is in the cable from Driver Module to Pen Panel. Order cable.
  6. If bad value moved → fault is downstream. Restore Pen Panel cables and continue.

Step 4 — Swap Pen Panel (magnet room side)

  1. Restore equipment room Pen Panel cables to original positions.
  2. On the magnet room side of the Pen Panel swap: J72 ↔ J76 and J73 ↔ J75.
  3. Set filename to mj4_pp_mr and run GLD.
  4. Open results: gedit /usr/g/service/log/mj4_pp_mr_dd.txt
  5. If bad value did NOT move → fault is in the Pen Panel DD Filter. Order Pen Panel DD Filter.
  6. If bad value moved → fault is downstream. Restore Pen Panel cables and continue.

Step 5 — Swap DD lines at the magnet

  1. Restore magnet room Pen Panel cables to original positions.
  2. At the magnet: swap the two front DD lines with each other AND the two rear DD lines with each other.
  3. Set filename to mj5_magnet and run GLD.
  4. Open results: gedit /usr/g/service/log/mj5_magnet_dd.txt
  5. If bad value did NOT move → fault is in the cable from Pen Panel to magnet. Order cable.
  6. If bad value moved → fault is in the body RF coil (inside magnet). Call TSM for support.
⚠️ RESTORE ALL CABLES BACK TO ORIGINAL POSITIONS BEFORE LEAVING SITE

Results File Reference

FileContentsCommand
filename_mc.txtMulticoil bias channel readings — one row per channel. Bad channel shows different current values from good channels.gedit /usr/g/service/log/filename_mc.txt
filename_dd.txtDynamic disable line readings — one entry per DD line. Shows short/open value on the faulting line.gedit /usr/g/service/log/filename_dd.txt
Naming convention tip: Use initials + run number + brief description for each GLD run so you can track which swap each file corresponds to. Example sequence: mj1_base → mj2_dm_swap → mj3_pp_eq → mj4_pp_mr → mj5_magnet. This is critical if you need to share results with TSM.
Multicoil vs DD tip: Multicoil errors reference a specific coil by name or port. DD errors reference a line number (BLD 1–4, front or rear). GLD generates separate output files for each fault type — check both _mc.txt and _dd.txt if the fault type is unclear from the error log.
