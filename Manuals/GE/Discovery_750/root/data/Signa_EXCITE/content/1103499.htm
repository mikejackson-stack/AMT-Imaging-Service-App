VRE Hardware Diagnostics

This document contains information on the following VRE diagnostics:

  • ICN CPU Stress

  • ICN Memory Stress

  • ICN Hard Disk Health

  • ICN Hard Disk Stress

  • ICN Hard Disk Integrity

1  Diagnostic Link

Diagnostics → System Function → Recon → VRE Hardware Diagnostics

Diagnostics → Hardware Location → PGR Cabinet → Recon → VRE Hardware Diagnostics

Illustration 1:  VRE Hardware Diagnostics

2  Purpose

The purpose of each diagnostic is explained in the tables below.

Table 1:  Purpose of Diagnostics

Diagnostic Type Purpose
ICN CPU StressTo ensure that the ICN can withstand a CPU (Central Processing Unit) stress test.
ICN Memory TestTo stress the memory on the ICN. While this diagnostic is designed to stress the memory, it also makes heavy use of the DMA, main disk drive and motherboard of the respective ICN.
ICN Hard Disk HealthTo verify the SMART health status for all hard disks on an ICN. SMART refers to the Self-Monitoring Analysis and Reporting Technology system present on the ICN hard drives. SMART contains information about hard drive parameters, which can be used to predict failures.
ICN Hard Disk StressTo test the disk throughout for all of the hard disks on an ICN. Hard disks store acquisition data for certain applications in DVMR. This diagnostic essentially verifies the ICN hard disk performance is fast enough to keep up with the incoming data during acquisition.
ICN Hard Disk IntegrityTo test the integrity for all hard disks on an ICN. Hard disk store acquisition data for certain applications in DVMR. This diagnostic essentially verifies the ICN hard disks can be used to reliably store and retrieve data by writing a known pattern to the acquisition partitions, reading it back, and comparing the contents.

3  Components Tested

The ICN CPU Stress Diagnostic tests the ICN motherboard. The other diagnostics test the ICN hard disks.

4  Requirements

The ICN is turned on and has at least one network connection from the ICN motherboard Ethernet port to the Host.

6  Test Sequence

  1. Select the appropriate diagnostic from the VRE Hardware Diagnostics screen.

  2. Click [Run].

    NOTE:Once [Run] is clicked, do not click anywhere else in the Common Service Desktop until the test is complete. If it is necessary to abort the test prior to its completion, click [Stop].

  3. Ensure that the ICN passes the diagnostic by reviewing the status in the Test Results table.

7  Expected Results

7.1  Expected Results for ICN CPU Stress

The ICN CPU Stress diagnostic has either a passed or failed status. If the diagnostic has failed, review the error log and corresponding extended error messages for subsequent actions. Additional responses to the diagnostic's failed result are outlined in the table below.

Table 2:  Diagnostic Results

ResultDescriptionGE Field Action
PassedThe ICN passed the diagnostic.No further action required.
FailedThe ICN failed the diagnostic.
  1. Ensure the ICN is turned on. Go to ICN Identification to identify the ICN (Utilities → Toolbox → VRE → ICN Identification).
  2. Ensure that the Host-ICN Remote Shell diagnostic runs successfully.
    1. If the diagnostic fails, follow the steps described on the Help page for that diagnostic.
    2. If the diagnostic succeeds, rerun the ICN CPU Stress diagnostic.
  3. If the diagnostic fails after a second attempt, reboot the ICN. Wait until the ICN is fully enabled. Once the ICN is enabled, rerun the diagnostic.
  4. If the diagnostic fails after the ICN reboot, check the ICN. Go to ICN Identification to identify the defective ICN (Utilities → Toolbox → VRE → ICN Identification).
NOTE:If the ICN Ethernet port/cables are faulty, then all of the test for that ICN may fail. This does not apply to the IPMI Test, which has a separate Ethernet cable.

The current product configuration has a redundant motherboard Ethernet connection for each ICN.

7.2  Expected Results for ICN Memory Stress and ICN Hard Disk Health

The ICN Memory Stress and ICN Hard Disk Health diagnostics have either a passed or failed status. If either diagnostic fails, review the error log and corresponding extended error messages for subsequent actions. Additional responses to the diagnostic's failed result are outlined in the table below.

Table 3:  Diagnostic Results

ResultDescriptionGE Field Action
PassedThe ICN passed the diagnostic.No further action required.
FailedThe ICN failed the diagnostic.
  1. Ensure the ICN is turned on. Go to ICN Identification to identify the ICN (Utilities → Toolbox → VRE → ICN Identification).
  2. Ensure that the Ethernet switch is turned on.
  3. Ensure that the Host-ICN Remote Shell diagnostic runs successfully.
    1. If the diagnostic fails, follow the steps described on the Help page for that diagnostic.
    2. If the diagnostic succeeds, rerun the appropriate diagnostic (ICN Memory Stress or ICN Hard Disk Health).
  4. If the diagnostic fails after a second attempt, run the ICN Hard Disk Stress diagnostic.
    1. If the diagnostic fails, check the hard disk. Look at the System Error Log for the corresponding error message. This contains the slot number location of the hard drive. Go to ICN Identification to identify the ICN (Utilities → Toolbox → VRE → ICN Identification).
    2. If the diagnostic succeeds, rerun the appropriate diagnostic (ICN Memory Stress or ICN Hard Disk Health).
  5. If the diagnostic fails after a third attempt, run the ICN Hard Disk Integrity diagnostic.
    NOTE:The ICN Hard Disk Integrity diagnostic takes about 85 minutes to complete.

    1. If the ICN Hard Disk Integrity diagnostic fails, replace the hard disk. Look at the System Error Log for the error message. This contains the slot number location of the hard drive. Go to ICN Identification to identify the ICN (Utilities → Toolbox → VRE → ICN Identification).
    2. If the diagnostic succeeds, rerun the appropriate diagnostic (ICN Memory Stress or ICN Hard Disk Health).
  6. If the diagnostic fails again, replace the hard disk. Look at the System Error Log for the error message. This contains the slot number location of the hard drive. Go to ICN Identification to identify the ICN (Utilities → Toolbox → VRE → ICN Identification).
    NOTE:If the ICN Ethernet port/cables are faulty all the tests for that ICN may fail. This does not apply to the IPMI test, which has a separate Ethernet cable.

    The current product configuration has redundant motherboard Ethernet connection for each ICN.
