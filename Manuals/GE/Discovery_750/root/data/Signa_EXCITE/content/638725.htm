Host-ICN IPMI Ethernet Diag

1  Diagnostic Link

Diagnostics >> VRE Subsystem >> VRE Communications and Hardware Diagnostic

2  Purpose

The purpose of this diagnostic is to verify the IPMI remote communication link from the Host to the ICN(s).

This diagnostic uses the VRE configuration file (/w/config/vre.cfg) that specifies the IP numbers or the ICN(s) IPMI Ethernet interface.

3  Components Tested

  • Host eth1 port and cable and gigabit switch port that it is connected to

  • ICN(s) Ethernet port/LAN card/IPMI card

  • ICN IPMI Ethernet cable and gigabit switch port that it is connected to

4  Requirements

ICN(s) are turned on and has a network connection from IPMI Ethernet port to the Host.

6  Test Sequence

  1. Select the Host-ICN IPMI Ethernet diagnostic.

  2. Click [Run].

  3. Verify each ICN tested passed the diagnostic.

    NOTE:Once you click [Run], do not click anywhere else in the Common Service Desktop until the test is completed. If you need to abort the test prior to its completion, you must click [Stop].

7  Expected Results

Review the error log and corresponding extended error messages for subsequent actions. Additional responses to the diagnostic’s results are as follows:

Table 1:  

FaultProblem DescriptionGE Field Action
FailedThe ICN has failed the diagnostic.
  • Verify the failed ICN has power (it need not be running the OS).
    NOTE:The ICN is identified by its MAC Address label on the back of the ICN.

  • Verify Host to ICN network connectivity for the IPMI Ethernet port furthest left on the back of ICN.
    • Check first to see if tiny green LED (very indistinct!) is lit for the IPMI port.
    • Try swapping either the ICN IPMI to switch cable (or moving it to a different switch port), OR
    • Swapping the Host eth1 to switch cable (or moving it to a different port).
      NOTE:If the host eth1 port or cable is bad there will be several diagnostic failures as the entire MGD subnet will be offline.
