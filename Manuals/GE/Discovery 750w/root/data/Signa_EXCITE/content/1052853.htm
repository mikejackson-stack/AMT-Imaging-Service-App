VRF Hardware Diagnostics

1  Diagnostic Link

Diagnostics → System Function → Recon → VRF Hardware Diagnostics

Diagnostics → Hardware Location → PGR Cabinet → Recon → VRF Hardware Diagnostics

Illustration 1:  VRF Hardware Diagnostics

2  Purpose

The purpose of the ICN VRF Board Level Diagnostics is to test the VRF board hardware.

3  Components Tested

  • VRF SRAM

  • DMA engine

  • Filters

  • Registers

  • VRF to IRF interrupt capability

4  Requirements

If the RRX is not working properly, or if unsure about the RRX status, before executing the VRF Hardware Diagnostics, please apply dual fiber optic service loopback connector to replace product cable and prevent interference from the RRX.

5  Test Sequence

NOTE: (For 32-channel 4100 systems) Use the ICN Identification tool from the Common Service Desktop (Utilities → Toolbox → VRE → ICN Identification) to help distinguish ICN1 from ICN2.

(For 32-channel 4170 systems) Use the HART log to help identify the VRF1 from VRF2. From the Common Service Desktop, open Error Logs → HART Log → Current Status. Look for the item “vrf” in the BoardType column. Check the Board Location for this board (icn1 VRF1 or icn1 VRF2). The slot number indicates the physical location of the VRF. Slot 19 is located to the side of the ICN. Slot 13 is located at the center of the ICN.

  1. Select ICN VRF Board Level Diagnostics from the VRF Hardware Diagnostics screen.

  2. Click [Run].

  3. Ensure that the hardware passes the diagnostic by reviewing the status in the Test Results table.

    NOTE:If the test fails, note the approximate time. This time is needed to identify the time stamp suffix of the result file.

6  Expected Results

This diagnostic has a passed or failed status. If the diagnostic has failed, review the error log and corresponding extended error messages for subsequent actions. A failed status does not mean that the VRF is bad. Follow the error message to isolate the fault of the VRF hardware or other processes external to the VRF.
