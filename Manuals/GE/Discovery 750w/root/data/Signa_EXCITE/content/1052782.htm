Host- ICN Remote Shell

1  Diagnostic Links

Diagnostics >> System Function >> Recon >> VRE Communication Diagnostics

Diagnostics >> Hardware Location >> PGR Cabinet >> Recon >> VRE Communication Diagnostics

Illustration 1:  VRE Communication Diagnostics

2  Purpose

The purpose of this diagnostic is to verify remote shell connectivity to the ICN. This diagnostic attempts to execute a command on the ICN via the remote shell protocol.

3  Components Tested

Remote shell service on the ICN

4  Requirements

The ICN is turned on and has a network connection to the host.

5  Block Diagram

Illustration 2:  System Cabinet and GOC Diagram for VRE Communications

6  Test Sequence

  1. Select the ICN Remote Shell Diagnostic from the VRE Communication Diagnostics screen.

  2. Click [Run].

    NOTE:Once you click [Run], do not click anywhere else in the Common Service Desktop until the test is complete. If you need to abort the test prior to its completion, you must click [Stop].

  3. Ensure that the ICN passes the diagnostic by reviewing the status in the Test Results table.

7  Expected Results

The results of this diagnostic can be passed, failed, or no ICNs defined. If the diagnostic has failed, please review the error log and corresponding extended error messages for subsequent actions. Additional responses to the diagnostic's results are outlined in Table 1.

Table 1:  Diagnostic Results

ResultDescriptionGE Field Action
PassedThe ICN passed the diagnostic.No further action required.
FailedThe ICN failed the diagnostic.
  1. Ensure that the ICN is up.
  2. Run the Host-ICN Ethernet Path diagnostic to ensure the host to ICN network connectivity.
  3. Reboot the ICN.
No ICNs definedThe host has no ICNs defined.Refer to and run VRE Reconfiguration.
