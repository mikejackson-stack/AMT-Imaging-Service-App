VRE Troubleshooting Tips

1  ICN Switch On/Off Procedure

Assuming that all the Ethernet connections on the ICNs and GOC are wired correctly:

  1. The ICNs will automatically switch ON when the HP GOC is switched ON, and the system reaches the login prompt.

  2. The ICNs will automatically switch OFF when the HP Computer is switched OFF using the software in an orderly.

    • Turning off the HP Computer by switching OFF power to it or the GOC will not shut down the ICNs. The software running on the HP Computer must be brought down in order to affect the ICNs.

    • A blue LED on the front of the ICNs indicates the power is ON when illuminated, and power is OFF when extinguished.

NOTICE
The following is NOT a preferred solution. Perform only if no other option is available. If after 3 minutes the ICN has still has not shut down, HOLD the power button down on the ICNs to override the ICN OS and force a shutdown.
 
 

  1. If the HP GOC is locked up or inactive, bring the ICNs down manually as follows:

    1. Press the power button on the ICNs to bring the ICN OS down cleanly and shut off power to the ICNs. (There is a delay of 30 seconds after pressing the power button before the shutdown begins.)

    2. Wait for 3 minutes for the ICNs to shut off after closing all files.

  2. When a working GOC is brought back up, the ICNs should turn back on.

2   ICN Connections

  • All ICNs must have three connections to the Ethernet Switch (Example: 3 Com). Viewed from the rear, two connections are on the right side and one on the left.

  • The left connection is the diagnostics port. Through this port, the firmware is loaded onto the ICN.

  • Connection to the Infiniband light in the MGD Chassis is not initialized until the TPS resets. Infiniband LEDs might not be lit until the TPS reset is complete.

  • In a fully functional two-ICN system, the Infiniband Board green LED must be ON for all connected ICNs and the yellow LED also ON for the Primary/Master ICN.

3  ICN Software

  1. When loading software, upon selecting the number of ICNs, the system displays an error if the number detected does not match the ICNs selected. At this point, physically check the number of ICNs present to make sure the number selected matches the number the system detects.

    1. If the system detects more ICNs than selected, switch off the MGD chassis, load the OS, and switch it ON. Continue the software load as the number of ICNs will then match.

    2. If the system detects fewer ICNs than selected, check power to the ICNs, that is all the IPMI cables to the ICNs (farthest left Ethernet connection when facing the back of the ICN). Make sure it is properly seated on both ends.

    3. Try swapping Ethernet cables or try another port on the Ethernet Switch before checking for a defective ICN.

  2. After the OS load if all the ICNs (four in this example) are loaded successfully, the system will indicate 4 ICNs are loaded. If only three are loaded, it will indicate 3 out of 4 are loaded, which means the system detected the 4th ICN, but could not load OS onto it. Contact GE Support for assistance.

    • After the ICN OS load, a connection error reported from the Infiniband Board is normal. Software will prompt to acknowledge.

    • Even though OS on the ICNs is loaded successfully, the green light on the Infiniband Board will not illuminate until the TPS reset is complete.

  3. During boot up, if the MGD Chassis encounters boot problems (hardware or software), a host communication time out error will result, but will not specify MGD issues.

    Try to ping APS, ping AGP, ping SCP and the term server. If successful, perform the mgd_term to watch boot errors when the MGD Chassis is recycled.

  4. When the ICNs are not recognized, and the blue LED is OFF:

    1. Do not pull out the ICN, remove the cables or tamper with the hardware.

    2. Note the MAC address of the ICNs with LEDs extinguished, and switch these ICNs OFF.

      Refer to ICN ON/OFF Procedure. For instructions on ICN replacement, refer to VRE Replacements.

4  Power Failure

In the event of a power outage, go through the normal power up procedure from the GOC. If one of the ICNs does not power ON, proceed as follows:

  • Try to reload the ICN OS using the normal procedure from the Common Service Desktop.

  • If there are discrepancies in the number of ICNs configured and the number detected, return toSection 1.

5  IP Address Changes and VRE ICN Reconfiguration

NOTICE
Verify that the IP addresses are up to date (both Host IP and MGD IP) during new installations and upgrades. If any changes were made to an IP address, follow the instructions in Reconfigure the ICN.
 
 

Problems that occur:

  • During application startup, some or all of the ICNs may not successfully initiate, and TPS reset failures will occur if the ICN was not reconfigured since the last IP address change.

  • Changing the Host IP address or MGD IP address without performing an ICN reconfiguration leaves information pertaining to the old IP addresses in the VRE configuration files.
