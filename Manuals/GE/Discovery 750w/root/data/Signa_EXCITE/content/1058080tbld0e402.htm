EM_LARGE_DIFFERENCE_DETECTED.

Large difference was detected between the two Power Monitors. Difference is in the (Long/short term) Average.

  1. Monitor 1 reads XX W/kg
  2. Monitor 2 reads YY W/kg
The power levels detected by the UPMs differ greatly.
  • Error can occur during the calibration process. If this error occurs during UPM Calibrations, ignore.
  • Error can also occur during troubleshooting if UPM boards have been swapped. Return boards to original spot or run UPM calibrations.
  1. Calibrate and run the UPM functional check.
  2. If error continues, go to Section 7 and swap the RF Detector boards. Recalibrate and run the UPM functional check. If lower value follows board, order new board. Try replacing one board, recalibrate and run the functional check. If error continues, replace other board; recalibrate and run functional check.
  3. If lower RF value does NOT follow RF Detector board, swap the cables running into the RF Detector boards. Recalibrate and run the UPM functional check. If lower value moves to other UPM, then check resistance of both cable runs. If the resistance of the cables are equal, then replace the RF couplers internal to the effected RF Amp (couplers may not be the FRU, actual FRU is dependant on amplifier type).
  4. If lower value moves to other UPM, then check resistance of both cable runs. If the resistance of the cables are equal, then replace the RF couplers internal to the effected RF Amp (couplers may not be the FRU, actual FRU is dependant on amplifier type).
  5. If steps 1-4 do not fix the issue, then replace the UPM Processor board within the UPM chain experiencing faults.
EM_TOO_MUCH_REFLECTED_POWER

UPM1/2 detected more reflected power than forward power on the (Head/Body/MNS) Amplifier.Possible cause is swapped Forward and Reflected Power Cables.

Forward Power = XX W

Reflected Power = YY W

Coil Reflected Power = ZZ W

UPM detected that there was more reflected power than forward power.
  1. If this error occurs during reflected UPM calibrations, then ignore.
  2. Check to make sure UPM cabling matches block diagrams.
  3. Make sure that there are no opens in the transmit chain. Opens could cause equal power for forward/reflected that could trigger this fault.
  4. If 1-3 are not applicable, then go to Section 7 and swap Detector boards to determine if error moves as well.
EM_UPM_FPGA_SN_FLT

The (UPM1/2) has detected that the FPGA was unable to read serial number information.

The FPGA was unable to read serial number information from (RF Detector/RF Processor) UPM board. This could be caused by an old revision of FPGA code or a hardware problem.
  1. Go to Section 7 and swap Detector boards to see if fault moves. If so, replace faulty Detector board.
  2. If root cause not determined, go to Section 7 and swap Processor boards to see if fault moves. If so, replace faulty Processor board.
  3. If root cause not determined, replace the CAM Chassis.
EM_UPM_PWR_FLT_DETECT

The (UPM1/2) has detected an Invalid Power Fault on the (Head/Body/MNS/CW) Amplifier.

The UPM detected RF power out of an amplifier port that should not have been producing RF at that time.
  1. Capture the protocol/sequence that produces this error repeatedly, then follow the following steps.
  2. If only one UPM detects this error, then go to Section 7 and swap the effected RF Detector boards.
  3. If only one UPM detects this error and step 2 was attempted with no success, go to Section 7and swap the Processor boards.
  4. If both UPMs indicate this failure, or steps 2 and 3 were attempted with no success, then proceed with troubleshooting the un-blank signal and affected RF Amplifier, as this indicates a system fault. It is also possible that external RF noise or some event has brought RF Hub out of stand-by state during RF transmit thereby interrupting Unblank signal to UPMs. Look in error log for other messages that occurred within 5 seconds before or even after this one that may help confirm this.
EM_UPM_PWR_LIMIT_EXCEED

The (UPM1/2) detected a Power Fault on the (Short/Long Term) Average.Calculated Average =XXLimit =XX

 This indicates that the UPM detected power that exceeded the trip limit for the area scanned.
  1. Customer should check the protocol to determine if it produces excessive SAR. Protocol should be approved by GE Apps specialist, if applicable.
  2. If the protocol is acceptable, calibrate UPM and run the UPM functional check.
  3. If the trip is consistently on one UPM, proceed to Section 7 and swap the RF Detector boards. Make sure to recalibrate the UPM after the swap. If the faults follow the RF Detector board, replace it. If the fault doesn’t follow the RF Detector board, replace the CAM Chassis.
EM_RF_NB_BOARD_MISSING

NB Detector Board Missing

UPM detects that a NB RF Detector board is missing
  1. Attempt to reseat both RF Detector boards, check for bent/broken pins on backplane and board.
  2. Proceed to Section 7 and swap Detector boards.
  3. If error doesn’t follow the Detector board, proceed to Section 7 and swap Processor boards to see if fault moves. If so, replace faulty Processor board.
  4. If the cause of error cannot be determined by Steps 1-3, replace CAM Chassis.
EM_RF_BB_BOARD_MISSING

MNS Detector Board Missing

UPM detects that a MNS RF Detector board is missing.
  1. If the detector boards are indicating a cable-missing fault, place a 50-Ohm terminator in the effected port. If error continues, replace the Detector Board.
  2. If the error goes away, determine where in the cable chain the connection is lost by using a DMM and checking for 50 Ohm resistance between the shield and center pin. You can also test by swapping cables along the chain to see where the failure occurs. If the error remains, replace the RF detector board.
  3. If the processor board unblank error occurs, check the voltage between pins 1 and 6 of the cable into the processor boards. The voltage should be between 2 Volts and 3.3 Volts. If it falls out of this range, then troubleshoot the cable chain back to the Driver Module. If the voltage appears okay, proceed to Section 7 and swap processor boards to see if fault moves. If so, replace faulty Processor board.
  4. If Step 2 doesn’t determine root cause, use a DMM to check the continuity of the cable connected to it. If it is bad, replace the cable.

This fault occurs when the UPM processor board detects incorrect power from the power supply. This is due to a failed power supply, backplane, processor board or a processor board or power supply that is not seated correctly in its slot.
  1. Pull out and reseat both processor boards and the power supply. Run the UPM Analog Diagnostics to see if the error has cleared.
  2. Check the voltages using a DMM at the Input Panel of the UPM. If these voltage levels confirm the fault description, then replace the UPM Power Supply.

  4. Check that the incoming power to the CAM is 110 to 130VAC 50/60Hz.
  5. If the error continues after attempting the above, replace the CAM Chassis, as it this indicates a failure.
