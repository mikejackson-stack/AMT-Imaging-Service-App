Results of Resetting the TPS

Last Updated:08/31/2005

1  TPS Reset Start-Up Failures

By connecting directly to the APS, SCP, and AGP, any startup failure can be seen. To view the APS/AGP/SCP outputs, open a C-Shell and type mgd_term. This will open 3 GUI’s which will display the output of each device. A sample of an interconnect failure is shown in Illustration 1.

  • SCP, see Illustration 4.

  1. The source of the error can be determined by using the Err No Decoder tool which is accessed from the Common Service Desktop by selecting [Utilities]. Click on [Err No Decoder] and then click the [Start…] button.

  2. The Err No Decoder will prompt: Please enter the error No. (s or q to quit). Enter the error number displayed in the APS window without the leading zero. Press <Enter>and the utility will return a description of the error.

  3. Type s or q and then press <Enter> to exit the Err No. Decoder program.

2  Other TPS Reset Failures

Other TPS reset failures may not cause a TPS startup failure in the APS window. These types of failures may cause a window to “hang” or the window may display a different type of error message.
