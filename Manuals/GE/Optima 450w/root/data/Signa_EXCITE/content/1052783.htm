ICN CPU Stress

1  Diagnostic Link

Diagnostics >> System Function >> Recon >> VRE Hardware Diagnostics

Diagnostics >> Hardware Location >> PGR Cabinet >> Recon >> VRE Hardware Diagnostics

Illustration 1:  VRE Hardware Diagnostics

2  Purpose

The purpose of this diagnostic is to ensure that the ICN can withstand a CPU (Central Processing Unit) stress test.

3  Components Tested

ICN motherboard

4  Requirements

The ICN is turned on and has at least one network connection from the ICN motherboard Ethernet port to the Host.

5  Block Diagrams

Illustration 2:  System Cabinet and GOC Diagram

6  Test Sequence

  1. Select the ICN CPU Stress diagnostic from the VRE Hardware Diagnostics screen.

  2. Click [Run].

    NOTE:Once you click [Run], do not click anywhere else in the Common Service Desktop until the test is complete. If you need to abort the test prior to its completion, you must click [Stop].

  3. Ensure that the ICN passes the diagnostic by reviewing the status in the Test Results table.

7  Expected Results

This diagnostic has either a passed or failed status. If the diagnostic has failed, please review the error log and corresponding extended error messages for subsequent actions. Additional responses to the diagnostic's failed result are outlined in Table 1.

Table 1:  Diagnostic Results

ResultDescriptionGE Field Action
PassedThe ICN passed the diagnostic.No further action required.
FailedThe ICN failed the diagnostic.
  1. Ensure the ICN is turned on. Go to ICN Identification to identify the ICN (Utilities >> Toolbox >> VRE >> ICN Identification).
  2. Ensure that the Host-ICN Remote Shell diagnostic runs successfully.
    1. If that diagnostic fails, follow steps described in the help page for that diagnostic.
    2. If that diagnostic succeeds, re-run the ICN CPU Stress diagnostic.
  3. If the diagnostic fails after a second attempt, reboot the ICN. Please wait until the ICN is fully enabled. Once the ICN is enabled, re-run the diagnostic.
  4. If the diagnostic fails after the ICN reboot, check the ICN. Go to ICN Identification to identify the defective ICN (Utilities >> Toolbox >> VRE >> ICN Identification).
NOTE:If the ICN Ethernet port/cables are bad then all of the test for that ICN may fail. This does not apply to the IPMI test which has a separate Ethernet cable.

NOTE:The current product configuration has a redundant motherboard Ethernet connection for each ICN.
