Driver Module Theory

  • The Driver Module communicates with the Host Computer through CAN (Control Area Network) Communication to receive its configuration data and to report on status and errors.

  • The Driver Control Board (DCB) with its CAN Communication Core (CCC) daughter board is the module’s intelligence, main interface and control.

  • The module contains an AC-DC power supply which supplies power for the module itself, the CAN network (up to 32 nodes), the multicoil and head preamps, the Cross-Point Switch and the LPCA (Low Profile Carriage Assembly).

  • Since the driver module is the source (24-volts) for the entire CAN network, if you lose that supply, the whole CAN network (to MGD Chassis and RRF Chassis) will be dead.

  • The multi-coil configuration information is passed to the Driver Module during download. The Release 10.x coil configuration files contain voltage configuration information, channel selection, and open and short circuit detection levels.

  • The the power op amp on the Multicoil Driver Board can source and sink up to about 0.5 amp of DC Bias current. The positive output voltage is set up by a MUX circuit and the driver switching is accomplished with an analog switch at the front end of the op amps.

  • The output current of the MC drivers is sensed as a voltage drop across a resistor and appropriately scaled before being sent to the DCB for monitoring.

  • There are new filters on the pen panel to account for the increase in signal lines going into the magnet room. The MC Filter has 18 signals (16 drivers; 2 loop back) and the Preamp Bias Filter has 11 signals (5 power; 6 control).

  • Key power supply outputs are monitored. Although a failure may not prevent scanning, this monitoring will help identify the cause of a problem.

  • All driver outputs are monitored real-time during scanning. If a fault is detected the scan is stopped and actual values detected are reported in the error message.

  • Error messages should be much more helpful in pointing to the problem. The first driver detecting a fault is identified as well as a value in hex that states how many drivers detected faults. In addition, the expected value and the monitored value are reported.

  • An open circuit fault means that a driver has detected less than the allowable limit but greater than zero. Open circuits are detected with the MC drivers during transmit (unblank) when the drivers output should be positive. An example open circuit fault: expected limit = 350 ma and monitored value = 165 ma.

  • A transmit fault means that during transmit (unblank), the driver expected to source current (positive) but instead detected that it was sinking current (negative). An example transmit fault: expected limit = 350 ma and monitored value = –130 ma.

  • A short circuit fault means that a driver has detected current sunk more than the allowable limit and less than zero. Short circuits are detected with the MC drivers during receive (blank) when a selected driver output should be negative. An example short circuit fault: expected limit = –250 ma and monitored value = –400 ma.

  • A receive fault means that during receive (blank), the driver expected to sink current (negative) but instead detected that it was sourcing current (positive). An example receive fault: expected limit = –250 ma and monitored value = 390 ma.

  • Hex mask of all failed channels indicates all monitored drivers that detected the fault. For example: 0x2 = 0000 0010 only the second driver detected a fault; 0x3c = 0011 1100 – potential cause CTLMID coil chosen but not plugged in.

  • At this time the HV (SW1), TR (SW2), and DD (SW3) disable switches on the driver module do nothing but light an LED and put a message on the screen. To disable fault detection on the TR and DD drivers you must still use the disable switches on the SSM.

  • In order to disable fault detection of the MC driver you must disable the switch (SW4) on the driver module. You should not use the switch on the SSM because that will put the whole SSM into service mode.

Differences Between Driver Module and SSM Hardware

This section briefly describes some of the major hardware differences between the new Driver Module and the SSM (System Support Module):

  • The Driver Module only performs Multicoil, TR & DD driver functions as well as provide DC bias to preamps via the Cross-Point Switch and LPCA

  • Potential for up to 32 MC drivers in the driver module compared to 4 in the SSM. At this time only 8 independent MC channels are used. Therefore each channel in an array has an independent driver network instead of being shared.

  • The Driver Module uses CAN instead of MDS communication. CAN is faster (500 k-baud Vs. 9600 baud), has greater bandwidth, is parallel (which means one bad node won’t take them all out) and supports Peer-to-Peer and Event communication. Also, CAN-open is an off-the-shelf protocol and it is easier to add additional nodes.

  • The MC drivers in the SSM have fixed voltage outputs and fixed error detection levels. The MC drivers in the Driver Module are configurable with regard to positive output voltage and error detection levels.

  • Fault reporting is more intelligent with the Driver Module. Rather than simply informing which drivers an open or short was detected on, actual output levels detected are reported as well as how many drivers faulted using a hex mask.
