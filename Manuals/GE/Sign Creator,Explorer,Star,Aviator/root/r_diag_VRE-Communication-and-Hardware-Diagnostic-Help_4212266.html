VRE Communication and Hardware Diagnostic Help

Topic ID: id_SL2290619-618599

Diagnostic Link

Diagnostics > VRE Subsystem > VRE Communication and Hardware Diagnostic

Topic ID: id_SL2290620-618599

Purpose

The VRE Communication and Hardware Diagnostic tests the Ethernet network path between the host and ICN. Data used in the diagnostic is checked for integrity.

There are various components to this diagnostic. By default, they are all run for a single iteration. Each can be run independently for as many iterations as desired. Table 1 shows a summary of what each diagnostic does and when to use it.

Table 1. VRE Diagnostics Summary
Diagnostic Purpose When to Use
Host-ICN Ethernet Path Diagnostic Confirms that the host can contact each ICN via Ethernet.After installing new ICNs or anytime ICN failure seems to be causing TPS reset failure.
Host-ICN Ethernet Stress Diagnostic Performs a large data transfer from host to each ICN and confirms data integrity. If an intermittent ethernet issue between the host and ICNs is suspected.
Host-ICN IPMI Ethernet Diagnostic Confirms ICNs can be remotely controlled from the host.If an ICN does not power on/off correctly.
ICN CPU Stress Diagnostic Performs a one-minute stress test on the CPU.If an ICN is intermittently locking up.
ICN Process Verification Diagnostic Confirms all key processes are running on each ICN.If a software issue is suspected.
ICN Remote Shell Test Confirms OS is running on each ICN.When software/OS load issue is suspected, but Ethernet is working.
ICN Time Sync Diagnostic Confirms time is properly synchronized between ICN and system.

  • Errors in the log relating to scan

  • Command arriving before stop command

  • Not being able to scan

ICN Reconstruction Diagnostic Functionally tests each ICN’s capability of performing image reconstruction. In doing so, each ICN will have its components tested, i.e. memory, processors, hard disk, software, etc.This test takes a set of raw data previously collected, and reconstructs the whole set several times, verifying image integrity by performing Checksums on the images and validating them against saved Checksum values.
ICN Hard Disk Health Diagnostic Verifies the Self-Monitoring Analysis and Reporting Technology (SMART) health status for both hard disks on an ICN. SMART refers to the system present on the ICN hard drives, and contains information about hard drive parameters, which can be used to predict failures.Anytime ICN failure seems to be causing TPS reset failure or If an ICN is intermittently locking up.
ICN Memory Stress Diagnostic Stresses the memory on the ICN. While designed to stress the memory, this diagnostic also makes heavy use of the DMA, main disk drive, and motherboard of the respective ICN.Anytime ICN failure seems to be causing TPS reset failure or If an ICN is intermittently locking up.
Topic ID: id_SL2290625-618599

Components Tested

  • Host Ethernet Interface

  • Host to VRE Switch Ethernet Cable

  • VRE Switch to ICN Ethernet Cable

  • ICN Ethernet Interface

  • VRE Switch

  • ICN Hard Disks

  • ICN Memory

  • ICN Motherboard

Topic ID: id_SL2290634-618599

Requirements

  • All Ethernet cables are connected from the Host to the VRE Ethernet switch.

  • All Ethernet cables are connected from the ICN to the VRE Ethernet switch.

  • ICN is turned on and enabled.

Note:

Once Run is clicked, do not click anywhere else in the Common Service Desktop until the test is completed. To abort the test prior to its completion, click Stop.

Test Sequence

  • Verify all Ethernet cables are connected per Requirements.

  • Execute diagnostic.

  • Verify each tested ICN passed the diagnostic.

Topic ID: id_SL2290641-618599

Expected Results

Review the error log and corresponding extended error messages for subsequent actions. Additional responses to the diagnostic’s results can be found at the links to the individual diagnostics in Table 1.
