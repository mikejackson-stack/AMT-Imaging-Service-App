If the fault is for a RRxPPort, check for short circuit faults -10V or +10V analog power faults are possible if there are many short circuit faults detected by the same RRxPPort.
Coil ID invalid or coil ID failure. The DPP reports an invalid coil ID or a coil ID failure. Run the Coil ID Functional Diagnostic.
Receiver module power supply failure. The DPP cannot run the bias checks because an Receiver module power failure was detected. This error could be caused by swapped cable track cables and too many short circuit faults.
  1. Run the Receive Chain Board level diagnostic under Receiver Diagnostics.
  2. Check for the swapped cables.
Rx Distribution power supply failure. The DPP cannot run the bias checks because an Rx Distribution power failure was detected. Run the Receive Chain Board Level diagnostic under Receiver Diagnostics.
Open circuit fault. An open circuit fault is detected on a coil channel. If another coil is available with the same multicoil bias channels, run the diagnostic again with that coil. If that coil is known to be good, and an open circuit fault is still seen, then the problem is on the system.

Use the Coil Datapath Diagnostic to troubleshoot system open circuits, or to prove that the system does not have open circuits.
Short circuit fault on a connected coil. A short circuit fault is detected on a coil channel. Remove the coil and run the diagnostic again. If the short circuit fault is still present, then it is not an issue with the coil.

If the short circuit fault is not present without the coil, then it is likely that it is a short circuit in the coil.
Short circuit fault without a connected coil. A short circuit fault is detected on a channel that does not have a coil connected. Use the Coil Datapath Diagnostic to troubleshoot system short circuit faults.

Alternatively, the Multicoil Bias Diagnostic can be run with the same troubleshooting procedure as the Coil Datapath Diagnostic to isolate the short circuit in the system. To do this, disconnect ports or cables at the same location as the Coil Datapath Diagnostic and run the Multicoil Bias Diagnostic. If the short circuit goes away at any point, it means that it was in the parts or the interface to the parts that were disconnected. Check for bent pins at every connection.
Tolerance/drive fault. A tolerance/drive fault is detected.
  1. Check if the receiver had power faults from too many short circuits or not.
  2. If there were no power faults, then the RRxPPort is probably bad.
ERROR: Error occurred checking bias. Generic error message over bias line.
  1. Check the other error message and identify the root cause.
  2. Check the cable connection referring to the block diagram.

Additional responses to the diagnostic's results are outlined below.

Table 3. Diagnostic results
Result GE field action
Passed No further action required.
Failed
  1. Make sure the ICN is turned on. Go to Utilities > Toolbox > VRE > ICN Identification to identify the ICN.
  2. Make sure all the cables (Ethernet, PCIe, and so on) are properly connected to the ICN.
  3. Make sure the Host-ICN Remote Shell diagnostic runs successfully.
    • If that diagnostic fails, follow the steps described in the help page for that diagnostic.
    • If that diagnostic passes, re-run the ICN CPU Stress diagnostic.
    • If that diagnostic passes, re-run the ICN Intensive Hardware diagnostic.
  4. If the diagnostic fails after a second attempt, reboot the ICN. Wait until the ICN is fully enabled. Once the ICN is enabled, re-run the diagnostic.
  5. If the diagnostic fails after the ICN reboot, check the ICN. Go to Utilities > Toolbox > VRE > ICN Identification to identify the defective ICN.
note: If the ICN Ethernet port/cables are bad, then all of the tests for that ICN may fail. This does not apply to the IPMI test, which has a separate Ethernet cable.
note: The current product configuration has a redundant motherboard Ethernet connection for each ICN.
