Applies to: GE Signa Excite (9x–15x), HDxt, HDx, Discovery MR450/750, Optima 450w/750w. Covers MGD-BOOT (MGD fails to reach Applications level), MCP820-NVRAM (board halted at MCP820-Bug/Diag prompt), host computer diagnostics, and APS/AGP/SCP troubleshooting.

MGD-BOOT — MGD Fails to Reach Applications Level

The MGD (Magnet Gradient Driver) must boot through several stages before it reaches "Applications" level. A failure at any stage leaves the system unable to scan. Use mgd_term to watch the boot sequence in real time.
CheckAction
Connect to MGD serial terminalLogin as root or operator. Open a shell window and type: mgd_term. This connects to the MGD serial console so you can watch the boot sequence.
Cycle MGD powerPower-cycle the MGD chassis (breaker in equipment rack or dedicated power switch on MGD cabinet). Watch the terminal for boot output.
Check for key boot messagesA successful boot shows these messages in sequence:
• No errors in OS Error Log Buffer
• Auto start of Tardis done
• Network is OK
• Start-up Complete
Missing or replaced-by-error messages indicate which subsystem failed.
Board Fail LEDA lit Board Fail LED on any MGD board = that board failed its self-test. Note which board and slot before any further troubleshooting.
OS Error LogIf boot halts early, read the OS error log from the terminal. Note the specific error string — it identifies the failed subsystem (network, Tardis clock, APS, AGP, or SCP).
Tardis / Real-Time Clock"Auto start of Tardis done" must appear. Tardis is the real-time clock subsystem on the MGD. If Tardis fails, the system cannot synchronize timing for gradient pulses. Check Tardis battery on the MGD CPU board.
Network check"Network is OK" confirms MGD can communicate with the host computer. If network fails: check Ethernet cable between host and MGD, verify IP configuration, check for duplicate addresses.
APS / AGP / SCP statusAfter network comes up, the APS (Analog Power Supply), AGP (Analog Gradient Processor), and SCP (Scan Control Processor) are initialized. Errors at this stage indicate a specific board fault — match error to board and replace or reseat.

MCP820-NVRAM — Board Halted at MCP820-Bug> or MCP820-Diag> Prompt

80% of MCP820 field returns are NVRAM corruption, not hardware failure. Always attempt the NVRAM recovery procedure before ordering a replacement board.
Symptom / StepAction
Board halted at MCP820-Bug> promptThe MCP820 stopped in debugger mode during boot — NVRAM configuration is corrupt or missing. Do NOT power-cycle yet. Proceed with CNFG check.
Board halted at MCP820-Diag> promptBoard entered diagnostic mode. Same root cause as Bug prompt — NVRAM issue. Proceed with same recovery steps.
Check CNFG dataAt the prompt, type: CNFG and press Enter. Review the output for any question marks (?) in the configuration fields. Question marks = that CNFG field is blank or corrupt.
Check Timekeeper batteryMeasure voltage on the Timekeeper (Dallas DS1287 or equivalent) chip on the MCP820 board. If battery voltage is below 3.0V, replace the Timekeeper chip. A dead Timekeeper causes NVRAM loss on power-down.
Re-enter CNFG dataType: CNFG;M and enter configuration data from the board label (serial number, board type, etc.). Field values are printed on the sticker on the MCP820 board itself.
Verify environment settingsAfter re-entering CNFG, type: ENV;D to display the current environment variables. Verify they match expected values for the system.
Power cycle and verify bootPower-cycle the MGD chassis. Board should now complete boot normally. Connect mgd_term and verify "Start-up Complete" message appears.
If recovery fails — board replacementIf CNFG recovery does not resolve the halt, board hardware failure is confirmed. MCP820 part numbers: 2294300-14, -16, -18, or -23 (verify correct revision for your system).

MGD / Host Communication Architecture (GE HDxt / Excite)

Board / ComponentFunctionLocation
MGD CPU / MCP820Main processor for the MGD chassis — runs OS, coordinates all MGD functions, communicates with host via EthernetMGD chassis — CPU slot
APS (Analog Power Supply)Provides precision analog voltages to gradient amplifiers and other analog subsystems. APS faults cause scan failures and boot errorsMGD chassis
AGP (Analog Gradient Processor)Processes gradient waveforms from the SCP and drives gradient amplifiers. AGP errors cause gradient-related faultsMGD chassis
SCP (Scan Control Processor)Top-level scan controller — receives scan prescriptions from host, generates pulse sequences, coordinates all subsystems during scanningMGD chassis
Host Computer (Octane / SGI / Linux)Runs the MRI application software, sends scan prescriptions to MGD via Ethernet, receives image dataEquipment room rack
TardisReal-time clock subsystem on MGD CPU board — synchronizes timing for all pulsed operationsOn MCP820 board

Tip: When troubleshooting MGD-BOOT, always connect mgd_term before power-cycling. The boot sequence messages scroll quickly and you'll miss the failure point if you aren't watching. The exact error message tells you exactly which board or subsystem failed.
Tip: MCP820-NVRAM failures frequently follow a power outage or UPS failure. If a site had a power event and the MGD won't boot the next day, go straight to CNFG;M recovery before ordering any parts — it resolves 4 out of 5 cases.
