Verifying SaveInfo Media (11.0)

The checkINFO program is used to verify contents of the SaveInfo data on the system disk and on the actual SaveInfo MOD. The program checks the system disk for proper files and file size.

If discrepancies are discovered, the program will report what is wrong. The program will halt, and not check the SaveInfo MOD for proper file structure. If the SaveInfo structure is correct, the program will automatically check the contents of the SaveInfo MOD.

There are three methods to execute the checkINFO command:

  • checkINFO -pre: Performs check on system disk only.

  • checkINFO -post: Performs check on MOD only.

  • checkINFO: Performs check on both system disk and MOD. (The program will not perform a check on MOD if issues are found on the system disk.)

Running a complete checkINFO on both System and MOD requires about 60 seconds. Proceed as follows:

  1. Insert the already created SaveInfo MOD into the MOD drive.

  2. Ensure Signa Software is up and running on the Host computer.

  3. Navigate to the Service Desktop and open a C-shell.

  4. Log in as root by typing: su - and press <Enter>. Password is operator.

  5. Change directory to the bin directory by typing: cd /usr/local/bin<Enter>.

  6. Start the verification by typing: checkINFO (case sensitive) and press <Enter>.

First the program ensures the files on the host scanner that are normally written to a SaveInfo MOD are present and not corrupted. Next, the program checks that saved information on MOD matches what is on the system. (See Illustration 1for an example of a successful check.)

Illustration 1:  Passed SaveInfo Check

  • If issues are noted during with the SaveInfo data on the system disk, they must be corrected in order to successfully transfer data to the SaveInfo MOD. Potential causes for failures are excessive file size (greater than 40 mb) or special characters, such as *(&$#@ in the character string that may have been used when customers created protocols.

  • If issues are found, a message will display informing the operator with a list of files that need to be moved or fixed in order for the SaveInfo to properly archive to MOD. Discuss issues with the customer, and attempt to fix the offending files or move them to a temporary directory before starting a SaveInfo.

Example: If the file /usr/g/protocol/site/head/noggin scan is reported corrupted and it is not possible to fix it, it will need to be moved as follows:

  1. Create a temp directory:mkdir /usr/g/temp and press <Enter>.

  2. Move the file:mv /usr/g/protocol/site/head/noggin scan /usr/g/temp and press <Enter>.

  3. Perform a SaveInfo.
