1  BEFORE YOU BEGIN THE SOFTWARE LOAD - CAUTIONS AND WARNINGS

NOTICE
During the Install GUI phase of the software load, be sure the <Num Lock> key on the key board is turned off. If the <Num Lock> is on, the symptom seen is that nothing will happen when trying to type in any of the edit fields in the Install GUI.
 
 

NOTICE
When reconfiguring the system using the Install/Configuration GUI, remember to push the [Configure] button on the verify tab before going to the Save info tab and doing a SaveInfo. If you have not done the final configuration by pushing the [Configure] button in the Verification tab, the information saved during Save Info will not reflect the latest changes made in the Install GUI.
 
 

NOTICE
If the site will be using the “YP” networking option, YP must be turned off, until after the InSite IIP option has been configured and checked out, or it will cause the InSite checkout to fail.
 
 

2  Required Media

  • PC Linux operating system CDROM.

  • MrApps - MR Applications CDROM

  • saveINFO - MaxOptix MOD Media (Either blank or previously used)

  • 2.3 GB MOD for system backups.

    NOTE:Ensure the MOD used is 2.3 GB and not a 1.2 GB disk. The 1.2 GB MOD's will not work with the system MOD drive.

3  Archive Images

This installation instruction will erase any current images left in the database. Archive all images BEFORE continuing with this procedure.

4  Required Information Prior To Loading Software

Vital site information is recorded to ensure proper software installation and configuration of the new software.

  1. With the system up and running, open a C-Shell from the Service Desktop. Login as root by typing: su root and enter password operator.

  2. A Message window will appear and ask "Would you like to invoke Guided Install…", Select Yes

  3. Step through each tab. Record the values from each field using the follwing Data sheets:

    • Site Configuration (Network Tab)

    • Site Configuration (System Configure Tab)

    • Site Configuration (Hardware Configure Tab

    • Site Configuration (Remaining Tabs)

    • System Options Data Table

  4. If this is a Mobile System, select [Mobile], then record all Site Names and IP addresses.

  5. If the site has Broadband connection, record the Gateway address.

5  SaveInfo and Saving System Information Entered In The Install GUI

5.1  SaveInfo

  1. Insert the SaveInfo MOD or a new MOD into the drive.

  2. Click on [Save Info] from the Install menu. The system opens the window called Xexec. (If the MOD has not been used, you will see a message regarding the use of the MOD for "Raw Data Storage"; choose [Overwrite].

  3. When asked: Do you really want to save configuration files to the Info MOD? [y|n], type: y<Enter>.

  4. At top left corner of the Install GUI, select [File] then [Save GI Configuration to MOD].

  5. Remove the MOD and write release version, the system name, and the date on it.

  6. When SaveInfo is complete, verify that the information saved correctly. See Verifying SaveInfo Data.

    NOTE:For systems upgrading to EXCITE (Octane computer to LINUX), checkINFO is not available on the Octane computer.

    NOTE:If site protocols are missing, please call OLC for support and do not proceed.

  7. At top left corner of the Install GUI, select [File] then [Save GI Configuration to MOD].

  8. Remove the MOD and write release version, the system name, and the date on it.

NOTE:The “Save GI Configuration to MOD” creates a copy of the information already entered in the GUI tabs for later use to update the tabs during a software reload. The [Save GI Configuration to MOD] and SaveInfo can be saved on the same side of the Info MOD. A separate partition is built for each.

5.2  SaveInfo Backup File

Beginning with software release Signa 9.1 and 10.0, whenever a SaveInfo is made a backup file is created of all the files saved to the SaveInfo MOD. This backup file is located in /usr/g/service/log/saveINFO.tar.gz and can be used to manually update configuration files in the advent the SaveInfo MOD becomes corrupted. It is suggested that a backup copy be keep by using FTP to move the file to the service laptop or other machine and saved. See Troubleshooting the Term Server for more information on this file.

5.3  SaveInfo Log File

SaveINFO now creates a log file in /usr/g/service/log directory called saveINFO.log. This file will list all the files that saveINFO was expecting to save but could not find on the system and hence could not save. Some of the files may be specific to TWIN or HFO or MGD systems and in those cases the log file will have a comment to that effect so that the FE is not confused. It is not required but is a good practice that this file is checked after a saveInfo to insure all files have been successfully saved.

During the SaveInfo, a backup copy of the tar file saved to MOD is also saved to the systems hard drive in directory /usr/g/tmp. The backup file is named, saveINFO.tar.gz. In the event that a SaveInfo MOD would become corrupted, the saveINFO.tar.gz can be unzipped using the gunzip command. (On the command line type: gunzip –h for help using gunzip). Copy the resulting saveINFO.tar file to a new MOD and do restoreInfo as required.

5.4  Record Site Coils

All GE coils will be included in the Site Coils List. You will want to remove the GE coils that your customer does not have after the load, so record the site coils currently listed in the Coil Config File as follows.

  1. From the Service Desktop, select [Utilities], then Config File Manager. Select Coil Config File.

  2. Record all coils below that are listed under Site Coils.

  3. Continue to Operating System Load.
