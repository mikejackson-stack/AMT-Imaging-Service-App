Troubleshooting the receive chain (DS-DPP)

Safety

Before working in any GE HealthCare MR suite or doing any GE HealthCare service procedure, you must:

  • Have read and understood all hazard conditions and safety requirements in the latest revision of the GE HealthCare MR Service Safety Manual (5452735).
  • Have successfully completed all relevant GE HealthCare Environmental Health and Safety (EHS) courses (or for non-GE employees, equivalent workplace training courses).
  • Comply with all site-specific training and workplace safety requirements.

If you have any safety concerns at any time, do not begin work or immediately stop work and move to a safe location. Immediately contact your supervisor or site safety officer for instructions on how to proceed.

Notice
Possible system performance issues
Leaving the system power on when removing any cables or modules during troubleshooting may cause damage to the electronics if they are unplugged or swapped while power is on.
Always turn the system power off before removing any cables or modules during troubleshooting.

DVMRlink error troubleshooting

All the fault conditions related to inhibit source are transferred through DVMRlink to host and shown as error message.

Topic ID: id_SL14252791-1178792

Fault condition of DVMRlink at DS-DPP RRx

Even if DVMRlink at DS-DPP RRx is down, DVMRlink from RxDist can transmit DS-DPP fault condition. In this case, the following error message will be shown.

On Error log

  • The optical signal dropped out on the DVMR fiber from ICE and RRX-[X] J[Y] Verify that fiber is securely connected.
  • Rx Dist module reports that the RRx-[X] module does not have good DVMR link with ICE module.

On ICE_term

  • ERROR: RRX-[X] J[Y] fiber lost signal detect.
  • ERROR : Fiber link Fault on RRx-[X].
  • ERROR : The lower/upper half on Pport RRx-[X] does not have a DVMR fiber link.
  • ERROR : Not enough receivers found, expected 7, found [Z].
Note: [X], [Y], and [Z] represent the DPP number, connector number, and receiver number, respectively. [X]=, [Y]=6/9, [Z]=0-6

For these errors, do the following troubleshooting.

Troubleshooting

  1. Examine whether the fiber cable is securely connected.
    • If no, seat the cable securely.
    • If yes, go to next step.
  2. Swap SFP module of error RRx with others.
    • If DVMR lost module # is changed, replace SFP module.
    • If DVMR lost module # is not changed, go to next step.
  3. Swap error DS-DPP RRx with the other DS-DPP RRx.
    • If DVMR lost module is changed, replace DS-DPP RRx.
    • If DVMR lost module is not changed, replace fiber cable/Rx Dist/ICE.
Topic ID: id_SL14252807-1178792

Fault condition of DVMRlink at RxDist is down

Even if DVMRlink at RxDist is down, ICE <-> RxDist copper link works for FRU isolation in RxDist. In this case, the following error message will be shown.

On Error log

  • The optical signal dropped out on the DVMR fiber from ICE to Rx Dist Verify that fiber is securely connected.
  • A RRX module is not sending status information back to IRF3/IXG/ICE board over its dual fiber cable. The command to Rx Dist could not be completed. Module RRX-6.

On ICE_term

  • ERROR: The Rx Distr fiber lost signal detect.
  • ERROR : The Rx Distr was not found on DVMR links.
  • ERROR : Not enough receivers found, expected 7, found 6.

For these errors, do the following troubleshooting.

Troubleshooting

  1. Examine whether the fiber cable is securely connected or not.
    • If no, seat the cable securely.
    • If yes, go to next step.
  2. Swap SFP module with the other RRx.
    • If DVMR lost module is changed from Rx Distr to RRx, replace SFP module.
    • If DVMR lost module is not changed, replace fiber cable/Rx Dist/ICE.

DS-DPP swapping for troubleshooting

Notice
Possible component damage
Failure to shut off power may damage the receivers.
Before swapping DS-DPP, always turn the system power off. Otherwise, it may cause system problems. Receivers are not designed to be swapped with the power on.
Important: You must physically swap the DS-DPP components. It is not possible to swap by cables only. If any DS-DPP components are swapped, return the components to their original position before completing the next action.

To examine whether the problem moves with DS-DPP or not, swap the DS-DPP components according to .

For replacement, see Replacing the Digitized Per Pin Remote Receiver (DPP RRx).

Topic ID: id_SL4165807-1178792

TPS reset fails due to receive chain loopback

During every TPS reset, the RRX Chain runs a loopback test to calibrate each Receive Channel for each R1 setting.

The loopback test stores a log file in the /usr/g/service/log directory.

The log file is named r1GainCal_date.dat (for example, r1GainCal_2015Aug14_154949.dat).

For each R1 value, for each channel, the measured energy drops by 3 dB ± 0.5 dB. If a channel falls outside the tolerance, the Pass/Fail column will indicate Fail for that channel. No entry indicates Pass.

The log file continues to R1 value = 1.

Example:

Review the Loopback Cal file:

  1. Open a C Shell.
  2. Type cd usr/g/service/log.
  3. Type ls –altr r1Gain*.

    This command will list all of the R1GainCal files with the most current file shown on the last line.

  4. Show the contents of the log file (use more, gedit, or view to show the contents of the file).

Diagnosing the issue:

  • The DS-DPP is responsible for setting correct R1 values, therefore the DS-DPP with corresponding channel would be suspect. However, it is best to run Diagnostics and follow the same troubleshooting steps shown in Example of a bad channel to make sure.
Topic ID: id_SL4176224-1178792

Intermittent multicoil bias faults

If the system is experiencing intermittent multicoil bias faults, try running a scan with and without RF enabled to see if there is any difference. There may be noise getting into the bias lines (possibly from a loose quick disconnect).
