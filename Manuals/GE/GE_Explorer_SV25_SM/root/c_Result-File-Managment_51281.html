Result File Managment

Once a gradlong scan is completed, the results files are created and stored in /usr/g/service/cclass. Result files are overwritten with each pass of gradlong. The tar.gz files are not overwritten unless the same prefix is specified in the “fpref=” argument. Display management commands work on whatever un-tarred result file is open.

  • Type gradlong mb0 to display all measured b0 residual field plots in percent vs sample time in msec, referenced from the end of the EC excitation pulse’s flat-top.

  • If you want to change the vertical y-scale of these plots, then type gradlong mb0 {yscale} where the new vertical scale be +/-yscale in percent (for example gradlong mb0 1.0).

  • Type gradlong mlin to display all measured linear gradient residual plots in percent vs. sample time in msec, referenced from the end of the EC excitation pulse’s flat-top.

  • If you want to change the vertical y-scale of the these plots, then type gradlong mlin {yscale} where the new vertical scale be +/-y-scale in percent (for example gradlong mlin 1.0).

  • A complete gradlong run summary can be found in the text file /usr/g/service/ cclass/gradlong.sum (check it out using “more gradlong.sum”, “cat gradlong.sum” or your favorite text editor).

  • Type gradlong show to display the EC calibration-related files, links and contents. This same output can also be piped to a text file by typing gradlong show >yourfilename for later transfer or use elsewhere, etc. Note that this same EC cal file information is also contained in the summary file “gradlong.sum,” which is created each time a gradlong measure run is made.

  • Results for each measurement “run” are automatically stored in a zipped tar file /usr/g/service/cclass/ [prefix.]gradlong.tar.gz where “prefix” may have been specified via the “fpref=prefix” switch when the gradlong measurement run was specified. The default prefix is a “null” or empty string. If you specify a prefix, then a period (“.”) will automatically be added between it and the word “gradlong” in the filename. A results tar file will always be created regardless of whether you specify a prefix or not. If you do NOT specify a prefix, the results tar file will be named “gradlong.tar.gz”. A gradlong measurement run will ONLY automatically delete a tar file of the same name it is about to create for the current measurement. Therefore, using unique prefixes can ensure that all measurement results can be retained for later examination. The prefixes “spt”, “spt_WHOLE” and “spt_ZOOM” should not be used when running gradlong standalone since these are already used when gradlong is run via SPT, and we do want to retain the latest versions of these results files from SPT. The SPT-generated gradlong results tar files can be unzipped and untarred just like any other. DO NOT delete the files [spt,spt_WHOLE, spt_ZOOM].gradlong.tar*.

  • Perform the following to examine results of a previously-saved gradlong run (i.e. not the immediately current run or just completed run but one “saved” by using the fpref=? switch):

    1. Type ls -l *gradlong.tar* to list the files you have to choose from in /usr/g/service/cclass.

    2. Type gradlong clean to delete all generically-named results files for the presently viewable data so these files will not be mixed or confused with data files coming from the next tar operation that unpeels a saved file.

      Note:

      This “clean” step is crucial.

    3. Type gunzip [prefix.]gradlong.tar.gz to unzip the tar file of interest. If this “unzip” operation has been previously performed on this file, go directly to the next step (i.e., the zipped file “*.gz” no longer exists after the first “unzip” operation on it).

    4. Type tar –xvf [prefix.]gradlong.tar to peel apart the tar file into fresh generically-named results files for the measurement run you now want to examine. This tar operation will list the files that are contained in and coming from the tar file.

    Now you’re ready to use gradlong’s “mlin”, “mb0”, “spec”, “show”, etc. switches to redisplay the plots measurement table and text information.
