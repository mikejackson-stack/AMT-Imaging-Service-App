SmartSnap theory

SmartSnap is an automated tool that captures logs, core dumps, memory dumps, and other debugging information.

Required conditions
Systems running software version 28.0_R04 or later.

Overview

SmartSnap is an automated tool based on the legacy sprsnap utility that captures logs, core dumps, memory dumps, and other debugging information that is needed by engineering to root cause problems on MR systems. SprSnap was intended and continues to be manually launched through Guided Install or from the command line. SmartSnap auto triggers sprsnap on key system failure points, collects data for troubleshooting, and keeps as much data as possible on the system to manually pull when critical problems may have occurred.

Information below relates to software release 28.0_R04 or later unless otherwise noted.

SmartSnap automated functionality

The SmartSnap tool automatically collects real-time/non-real-time log files:

  • After the host monitor is up.
  • When the system is not started up properly.
  • At system shutdown or restart initiated from the service desktop.
  • When improper shutdown is detected.
  • Whenever a TPS reset is done.
Depending on the above trigger cases, the SmartSnap filename will contain the tag described below.
Filename tagDescription
hardshutdownFor snaps that are taken at the detection of hard shutdown.
dailyshutdownFor snaps that are triggered when a system shutdown/restart happens using the daily button.
serviceshutdownFor snaps that are triggered when a system shutdown/restart happens using the service button.
abnormalshutdownFor snaps that are triggered when a system shutdown/restart happens using the other button.
manual, hmabnormal, or tpsresetStay as-is per the current, existing implementation.

The location of the SmartSnap continues to be: /export/home/snap/snapName.

For example: /export/home/snap/Bay5.b15.dailyshutdown.0710181151, where the SmartSnap was done after clicking the daily button for system restart/shutdown, for site Bay 5, host b15, on 2007, October, 18th, at 11:51.

Snap name convention is:

  • <hospitalName>.<hostname>.<type>.<YYMMDDHHMM>
Note: Use caution and inform the customer on the proper use of the Daily, Service and Other buttons on the shutdown/reboot dialog window as SmartSnap priorities follow each one (see below recommendations).

Recommendations and notes for field service activities

  • SmartSnaps are now started automatically on every restart and shutdown. However, the SmartSnaps are not finished until after the next restart so as to minimize customer downtime between when a problem is found and when the system can scan again.
  • SmartSnaps are taken automatically whenever a TPS reset is done.
  • If a customer restarts every day, then a SmartSnap will be taken every day and due to limited space, SmartSnaps will eventually be overwritten depending on priority. It is suggested that as soon as a complaint about a problem is made by a customer, the service person saves the SmartSnap or calls the OLC to do the save of the SmartSnap that is the closest one after the problem was detected.
  • Manual SmartSnaps take highest priority, then shutdowns/restarts by the operator using other rather than daily. Daily SmartSnaps have the lowest priority but will start overwriting higher priority SmartSnaps after 7 to 10 days, hence the need to save the SmartSnap as soon as practical.
  • Please ask the customer for the date and time of the actual incident, and record it in the Service Report (SR).
